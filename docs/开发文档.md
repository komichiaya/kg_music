# 酷狗音乐概念版桌面播放器 · 项目开发文档

> 版本：v1.0  ·  更新日期：2026-10-19  ·  状态：设计阶段
> 后端：KuGouMusicApi（NodeJS / Express，动态路由 `module/*.js`）
> 前端：music-app（Electron + Vue 3 + TypeScript + Vite + Element Plus + Pinia + Vue Router）

---

## 一、项目概述

本项目基于上游 `KuGouMusicApi` 提供的接口，构建一个**第三方、高颜值、概念版**的酷狗音乐桌面播放器。

定位关键词：

- **概念版**：不照搬官方客户端 UI，以重新设计的视觉语言呈现酷狗的音乐内容生态。
- **高颜值**：暗色优先、玻璃拟态（Glassmorphism）、极光渐变、克制的动效，强调留白与层次。
- **功能完整**：覆盖登录、搜索、播放、歌词、歌单、排行、个人中心、设置等核心闭环。
- **桌面原生**：基于 Electron，支持窗口控制、系统托盘、迷你模式、媒体键、跨平台打包。

四项基本需求（硬性要求）：

| # | 需求 | 实现要点 |
|---|------|----------|
| 1 | 酷狗音乐账号登录（扫码 / 手机 / 邮箱） | 三通道统一收敛为 `{token, userid, vipType, vipToken}` 凭证 |
| 2 | 支持歌词显示 | 逐行 LRC / KRC 双模式，当前行高亮 + 滚动 + 拖动定位 |
| 3 | 用户打开时自动签到 | 启动即校验会话并触发听歌等级同步（CSCC 上报） |
| 4 | 功能完整 | 播放器、搜索、歌单、排行、个人中心、设置全闭环 |

## 二、整体架构

### 2.1 进程模型

```
┌─────────────────────────────────────────────────────────────┐
│ Electron Main 进程（electron/main.ts）                        │

│  · 可选：内嵌或外挂 KuGouMusicApi（推荐随主进程拉起）          │
└───────────────┬─────────────────────────────────────────────┘
                │ contextBridge（preload.ts，最小化暴露 API）
┌───────────────▼─────────────────────────────────────────────┐
│ Renderer 进程（Vue 3 + Vite）                                │
│  · 视图层：路由页面 + 组件                                   │
│  · 状态层：Pinia stores                                      │
│  · 服务层：src/api/* 封装 HTTP，统一 baseURL 与 cookie 注入    │

┌───────────────▼─────────────────────────────────────────────┐

└─────────────────────────────────────────────────────────────┘
```

### 2.2 网络层约定

- **统一 baseURL**：`http://127.0.0.1:3000`（由 Main 通过环境变量或配置注入 Renderer）。
- **Cookie 注入**：上游支持 `?cookie=token%3Dxxx%3Buserid%3Dxxx`、请求体 `{cookie}`、`Authorization` 头三种方式。播放器统一使用 **`Authorization` 头**（`token=xxx;userid=xxx;vip_token=xxx`），由 `useAuth` store 自动附加。
- **凭据持久化**：`{token, userid, vip_type, vip_token, t1, dfid}` 落盘到 Electron `userData` 目录（加密存储，见 §7.3）。
- **代理规避**：本机若存在 `HTTP_PROXY/HTTPS_PROXY`，axios 会继承导致 socket hang up。Main 启动上游与 Renderer 请求时需剥离代理变量（详见 §11）。

## 三、后端接口对接表（KuGouMusicApi → 播放器功能）

> 路由规则：`module/*.js` 文件名即路由路径，`_` 替换为 `/`。所有接口经 `http://127.0.0.1:3000` 访问。

### 3.1 登录与凭证

| 功能 | 上游路由 | 模块文件 | 关键入参 | 出参要点 |
|------|----------|----------|----------|----------|
| 扫码·生成 key | `/login/qr/key` | `login_qr_key.js` | `type=web`（appid 1014） | `data`：二维码标识 key |
| 扫码·生成图片 | `/login/qr/create` | `login_qr_create.js` | `key`, `qrimg=true` | `data.url` / `data.base64`（DataURL） |
| 扫码·轮询状态 | `/login/qr/check` | `login_qr_check.js` | `key` | `status`：0 过期 / 1 等待 / 2 待确认 / 3 授权成功；status=4 时 cookie 回写 `token`、`userid` |
| 手机·验证码登录 | `/login/cellphone` | `login_cellphone.js` | `mobile`, `code` | 成功 `status=1`，cookie 写入 `token/userid/vip_type/vip_token` |
| 邮箱/账号密码登录 | `/login` | `login.js` | `username`, `password`, `code` | 同上，secu_params 解密后回 token |
| Token 刷新 | `/login/token` | `login_token.js` | `token`, `userid` | 静默续期，输出新 `token/t1` |
| 设备登录 | `/login/device` | `login_device.js` | `token`, `userid` | 获取设备态信息 |

**手机登录说明**：`/login/cellphone` 需要验证码 `code`。上游**不提供**真实号段的验证码下发（避免触发风控），验证码下发需用户在官方端获取或走滑块校验。播放器侧手机登录入口保留 UI，提示"请输入收到的验证码"，并对接 `verify_user_info`（滑块校验）作为兜底。

### 3.2 歌曲与歌词

| 功能 | 上游路由 | 模块文件 | 关键入参 | 出参要点 |
|------|----------|----------|----------|----------|
| 歌曲 URL | `/song/url` | `song_url.js` | `hash`, `album_id`, `album_audio_id`, `quality`(128/320/flac/high), `free_part` | `url`（**数组**，取 `[0]`），`status=2`+`fail_process` 表示需付费 |

> ⚠️ 实测校正（2026-10-19）：`hash` 必须与 `quality` 匹配，否则一律返回 `status=2`。
> 搜索结果里对应关系为：128→`FileHash`、320→`HQFileHash`、flac→`SQFileHash`、high→`ResFileHash`；
> `album_audio_id` 取 `MixSongID`。播放器需按音质选择 hash，并在无权限时逐级降级。
| 歌词搜索 | `/search/lyric` | `search_lyric.js` | `hash`/`album_audio_id`, `duration`, `keywords` | `candidates[]`，含 `id` + `accesskey` |
| 歌词下载 | `/lyric` | `lyric.js` | `id`, `accesskey`, `fmt`(krc/lrc), `decode=true` | `decodeContent`：解码后的 LRC/KRC 文本 |

**歌词流程**（关键，易踩坑）：

1. 取到歌曲后，先调 `/search/lyric` 用 `hash`+`duration` 命中候选歌词，得到 `id` 与 `accesskey`。
2. 再调 `/lyric?id=&accesskey=&fmt=lrc&decode=true` 获得可读歌词文本。
3. `fmt=krc` 可获得逐字 KRC（含时间戳与字级高亮），用于"卡拉OK"模式；`fmt=lrc` 为逐行 LRC。
4. 注意 `lyric.js` 仅在 `decode=true` 时才回 `decodeContent`，否则只返回 base64 `content`。

> ⚠️ 实测校正（2026-10-19）：歌词接口的成功标志是 **`status=200`**（与登录接口的 `status=1` 不同），
> 且 `/search/lyric` 的候选列表在响应**根节点** `candidates`，不在 `data` 内。
> KRC 行格式为 `[行开始ms,行时长ms]<字偏移ms,字时长ms,0>字...`，字偏移**相对行开始**。

> `[language:]` 是 base64(JSON)：`content[]` 可能有多块，`type:1` 为译文、`type:0` 为日文罗马音，
> 块数与顺序都不固定（必须按 type 取），每块行数与正文对齐；译文/音译无逐字时间。

## 四、核心功能设计

### 4.1 需求一：酷狗账号登录（扫码 / 手机 / 邮箱）

#### 4.1.1 登录页布局

- 单页三 Tab：`扫码登录` / `手机号登录` / `账号密码登录`。
- 居中卡片（玻璃拟态），背景为概念版主视觉（极光渐变 + 模糊封面流）。
- 未登录可"游客浏览"（仅试听/搜索，无个人中心与签到）。

#### 4.1.2 扫码登录流程

```
[点击扫码 Tab]
   │
   ├─→ GET /login/qr/key?type=web          → 得到 qrcode key
   ├─→ GET /login/qr/create?key=&qrimg=true → 渲染 base64 二维码
   └─→ 轮询 GET /login/qr/check?key=        （2s 间隔，TTL 180s）
            ├─ status=1 → "等待扫码"（二维码常驻，状态文案动态切换）
            ├─ status=2 → "已扫描，请在手机确认"
            ├─ status=3/4 → 成功：cookie 取 token/userid/vip_token
            └─ status=0 → "二维码已过期"，提供"刷新二维码"
```

- 轮询在前端用 `setInterval`，组件卸载/切 Tab 时立即 `clearInterval`。
- 成功后调 `/login/token` 做一次续期校验，再 `/user/info` 拉取资料，最后跳转发现页。

#### 4.1.3 手机号登录流程

```
输入手机号 → [获取验证码] → 输入验证码 → POST /login/cellphone
   │
   ├─ status=1 → 登录成功，收敛凭证
   ├─ 需要滑块 → 渲染 verify_user_info 滑块（兜底）
   └─ 失败 → 错误提示
```

> ⚠️ 验证码由用户在酷狗官方端接收后手动填入；播放器不下发真实验证码，避免触发风控（与上游约定一致）。

#### 4.1.4 邮箱/账号密码登录

```
输入 用户名/邮箱 + 密码 → POST /login
   ├─ status=1 → 成功，secu_params 解析得 token
   └─ 失败 → 提示账号或密码错误
```

#### 4.1.5 凭证收敛与持久化

三通道最终统一为同一份凭证对象：

```ts
interface KugouCredential {
  token: string
  userid: string
  vip_type: number
  vip_token: string
  t1?: string
  dfid?: string
}
```

- 持久化：经 IPC 写入 Main 进程，使用 Electron `safeStorage`（系统级加密）落盘到 `userData/credential.bin`。
- 启动恢复：Main 读取解密后通过 preload 注入 Renderer，`useAuth` 初始化。
- 失效处理：任意接口返回鉴权失败（401/`status!=1` 且提示 token 失效）→ 清除凭证 → 跳登录页。

### 4.2 需求二：歌词显示

#### 4.2.1 歌词获取链路

```
当前曲目变化
   ├─→ /search/lyric?hash=&duration=   → candidates[0] {id, accesskey}
   └─→ /lyric?id=&accesskey=&fmt=lrc&decode=true → decodeContent
```

- 优先 `fmt=krc`（逐字），降级 `fmt=lrc`（逐行）。
- 解析：`useLyric` composable 将文本解析为 `LyricLine[] = { time, text, words?:[{t,char}] }`。

#### 4.2.2 展示模式

| 模式 | 触发 | 效果 |
|------|------|------|
| 歌词页 | 点击播放栏封面 | 独立路由 `/lyrics`，沉浸式封面背景，当前行居中高亮并随进度滚动 |
| 桌面歌词 | 设置开关 | 置顶独立小窗，半透明描边，跟随播放进度 |
| 卡拉OK | KRC 可用时 | 逐字渐变高亮（从左到右扫光） |

> 2026-10-20 调整：原「侧栏歌词」与「全屏歌词（双击封面）」两种形态统一收敛为**歌词页**。
> 点击底部播放栏的歌曲封面进入 `/lyrics`；返回走路由历史（Esc / 标题栏后退 / 页内关闭按钮）。
> 歌词页**不重复实现播放控制**：进度条与上一首 / 播放暂停 / 下一首统一由常驻的 PlayerBar 承担，
> 页内只保留歌词本身与「点击行定位」交互（PlayerBar 是能力超集，另含音量 / 播放模式 / 队列 / 音质）。

#### 4.2.3 同步与交互

- `timeupdate` 事件驱动二分查找当前行，平滑滚动（CSS `scroll-behavior` + transform）。
- 点击任意行 → 跳转播放到该行时间戳（`audio.currentTime`）。
- 无歌词时显示纯音乐占位 + 封面动效。
- 歌词与播放进度偏差 > 0.4s 时以平滑过渡校正，避免跳变。

### 4.3 需求三：打开时自动签到 + 登录领取一天 VIP

#### 4.3.1 定义

上游无独立"每日签到"端点；播放器将"签到"定义为**登录/启动即完成的动作链**，其中"领取一天 VIP"为登录态成立后的明确动作：

1. **会话校验**：`/login/token` 续期 + `/user/info` 拉取资料，确认登录态有效。
2. **等级查询**：`/user/grade/info`（查询模式，无 d_sec）获取当前等级与累计时长。
3. **领取一天 VIP**：`POST /youth/day/vip?receive_day=YYYY-MM-DD`（真实路径 `/youth/v1/recharge/receive_vip_listen_song`，`source_id=90139` 固定，注释明确"需要登录"）。登录态成立后自动触发，刷新会员资格。
   > ⚠️ 实测校正（2026-10-19）：`receive_day` 是**日期字符串**（如 `2026-10-19`），不是「1 天」。
   > 传 `1` 会被酷狗拒绝并返回 `error_code=304001`（"日期格式错误"）。
4. **首播上报**：若播放队列非空且当日尚未上报，播放 `start` 事件即触发 CSCC 上报；播放结束 `end` 事件携带 `duration`（实际播放毫秒数，扣除暂停与拖动）完成等级同步（`grade_synced`），同时传 `d_sec`（上次查询的服务端累计秒）+ `diff_sec`（本次新增秒）联动 `/user/grade/info`。
   > 实现约定（2026-10-19）：`uuid`（32 位字母数字）+ `mid`（纯数字）由 `src/utils/device.ts` 生成并持久化，start/end 必须一致；上报按「账号 + 日期」只做一次，避免重复累计时长；`end` 不自动重试（超时也可能已记账）。

> 上游领取 VIP 相关模块：`youth_day_vip.js`（领取）、`youth_day_vip_upgrade.js`（升级奖励，`upgrade_vip_reward`）、`youth_month_vip_record.js`（领取记录，用于幂等校验）、`youth_vip.js`（广告上报后领取）。播放器以 `youth_day_vip` 为主路径。

#### 4.3.2 触发时机

登录成功与冷启动两条触发路径，均收敛到 `useAuth.boot()`/`afterLogin()`：

```
路径 A：登录成功（扫码/手机/邮箱任一通道）
   └─→ 收敛凭证 → afterLogin()
        ├─ /login/token 续期 + /user/info 资料
        ├─ /user/grade/info 等级
        ├─ /youth/day/vip?receive_day=YYYY-MM-DD   ← 当日未领则领取一天 VIP
        └─ 跳转发现页，个人中心展示"已领取一天 VIP"

路径 B：冷启动（app.whenReady → 恢复凭证 → useAuth.boot()）
   ├─ 无凭证 → 游客态，不签到、不领 VIP
   └─ 有凭证 → 同路径 A 的后续动作（幂等）
```

- **幂等（双键）**：`lastSignDate`（签到上报日幂等）+ `lastClaimDate`（VIP 领取日幂等，yyyy-MM-dd）。同日不重复触发；并用 `/youth/month/vip/record`（`latest_limit=100`）核对服务端近 100 条领取记录，避免本地与远端不一致时重复领取。
- **失败容错**：领取失败（已领过/活动结束/风控）静默处理，仅 Toast 提示，不阻塞登录与播放。
- **可感知**：个人中心展示"今日已签到 · 今日已领一天 VIP · 等级 Lv.X · 累计听歌 N 分钟 · VIP 到期时间"。
- **降级**：签到/领取失败不影响播放；状态独立于播放可用性。

#### 4.3.3 分层与状态

签到链全部在渲染层完成（上游服务由 Main 守护，不需要额外的签到 IPC）：

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 接口 | `src/api/report.ts` | CSCC `start`/`end`，解析 `playback_accepted` / `grade_synced` / `grade` |
| 接口 | `src/api/user.ts` | `/user/grade/info` 查询与 `normalizeGrade` 归一化 |
| 状态 | `src/stores/checkin.ts` | 链编排、按账号+日期幂等、播放上报会话、链路状态与文案 |
| 状态 | `src/stores/profile.ts` | 等级/会员快照，`applyGrade` 回写上报结果 |

## 七、关键技术点与风险

### 7.1 设备指纹与 dfid

- `/song/url` 受设备风控（`errcode 20028`），必须先取 `dfid`。
- `/register/dev` **必须用游客身份**调用（带真实 token 会返回 `data: []`）；`dfid` 落盘长期复用。
- cookie 键名是**裸 `dfid`**（非 `KUGOU_API_DFID`），否则模块读不到。
- `register/dev` 有频率限制，短时间反复重启会拿不到 dfid，失败不阻塞启动。

### 7.2 付费曲与试听

- 完整版失败（`status=2` + `fail_process=[pkg,buy]`）后自动带 `free_part=1` 重试，仅得 60s 片段。
- 60s 是内容版权边界，不可绕过；免费曲目完整可播。
- UI 必须区分"试听 60 秒"（酷狗源片段）与"不可播放"（非酷狗源降级），不合并表述。

### 7.3 凭据安全

- Renderer 不直接读写磁盘；凭据经 IPC 由 Main 用 `safeStorage` 加密落盘。
- preload 仅暴露最小 API（`window.kugou.signin.run()` 等），不开 nodeIntegration。

### 7.4 取流地址解析

- 上游把地址放在 `url` **数组**中（`body.url[0]`），不要写成 `body.url ?? ...`，`??` 对数组短路失败。

### 7.5 代理与网络

- 本机 `HTTP_PROXY/HTTPS_PROXY` 会被 axios 继承，调酷狗服务易 `socket hang up`。
- Main 拉起上游与发起请求前，剥离 `http_proxy/https_proxy` 变量；原生 `fetch`/`https.get` 不受影响。

### 7.6 路由与字段命名

- 歌单搜索结果 id 必须用 `gid`（`global_collection_id`），传 `specialid` 给 `/playlist/track/all` 会 `20010`。
- 歌单曲目字段是另一套命名（`name`/`singerinfo[]`/`albuminfo`/`timelen`），与 song 搜索不同构，需独立 normalizer。

### 7.7 歌词解码

- `/lyric` 仅 `decode=true` 才回 `decodeContent`，否则只有 base64 `content`。
- KRC 解码依赖 pako（zlib 解压），上游 `util` 已实现 `decodeLyrics`。

| P7 打包 | 交付 | electron-builder 出包（win/mac）、自启、托盘、检查更新 |

## 九、验收标准

- **登录**：三通道均可登录；扫码 180s 内完成；重启免登录；token 失效自动跳登录。
- **歌词**：随播放逐行同步；支持点击跳转；KRC 可用即逐字高亮；无歌词有占位。
- **签到**：每日仅触发一次；启动后个人中心可见"今日已签到"与等级；失败不阻塞播放。
- **播放**：免费曲完整播放；付费曲自动试听 60s 并标注；dfid 缺失不卡死。
- **完整**：发现/搜索/歌单/排行/我的/设置全部可用；迷你模式与媒体键可用。
- **视觉**：暗色主题落地；玻璃/极光/动效符合令牌规范；高 DPI 清晰；满足 AA 对比度。

## 十、运行与开发指引

```bash
# 1. 启动上游（剥离代理）
cd KuGouMusicApi
env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY node app.js
# 默认 http://127.0.0.1:3000，Swagger 见 /swagger

# 2. 启动播放器（开发）
cd music-app
pnpm install
pnpm dev          # Vite + Electron 热重载

# 3. 打包
pnpm build        # vue-tsc + vite build + electron-builder
```

- 配置：`music-app/.env` 中 `VITE_API_BASE=http://127.0.0.1:3000`（也可由 Main 注入）。
- 上游守护：推荐 Main 在 `app.whenReady` 时以子进程拉起 `KuGouMusicApi/app.js`，退出时一并回收。
