# 2026-10-26

## 移除进度续播 + 修复「换列表点第一行从旧曲进度起播」

### 用户反馈
1. 断点续播「时不时会出错」；
2. 不喜欢重开应用后从上次中断处继续，要求从 0 开始。

### 找到的 bug（对应「时不时出错」）
`play(track, list)` 先 `queue.value = [...list]`，再调 `playAt(index)`；
而 `playAt` 判断「是否同一首」用的是 `current.value?.hash === queue.value[index]?.hash` ——
队列已被替换，两边都来自新列表，**只要索引相同就恒等**，于是被误判成「点的是当前曲」，
`keepPosition = true`，新歌从**旧歌的播放位置**开始。
最典型的触发：当前在列表第 1 首，去另一个列表点第 1 首。

修复：
- `playAt` 增加 `keepPosition?: boolean` 选项，显式覆盖判断；
- `play(track, list)` 在替换队列**之前**记下 `previousHash`，用它与目标曲比较后传入。
  只有「真的同一首」才沿用位置。

### 移除进度持久化（按用户要求）
- `playerSession.ts`：删除 `StoredPosition` / `loadPosition` / `savePosition` / `clearPosition`
  与 3s、结尾 3s 的边界常量；`dropLegacyResume()` 改为 `dropLegacySession()`，
  启动时同时清掉 `position.v1` 与 `resume.v1`。
- `player.ts`：删除 `persistPosition` / `POSITION_SAVE_MS` / `lastPositionSave` / `touched` /
  `switching`（只为落盘守卫存在）；`restoreSession()` 恢复队列与当前曲但 `currentTime = 0`；
  `resolveStartSeconds(keepPosition)` 只对同曲重载返回当前位置，换曲一律 0；
  timeupdate / pause / seek / ended / beforeunload 里的落盘调用一并移除。
- 队列恢复保留：重开后播放栏仍是上次那首，只是进度归零。

### 实测
- 晴天播到 0:10 → 切到歌单点第一行「以父之名」→ 从 0:02 起播（修复前会是 0:10+）。
- 注入 `position.v1 = { position: 120 }` 后刷新 → 播放栏 0:00，且该键被清除。
- `npm run typecheck` 通过。
- 注意：测试时用户的上游服务没在跑，临时起了 `build/upstream`（端口 3000），验完已停。

## 歌单封面：改完详情页不更新（用户反馈后修复）

### 用户反馈
「修改完封面后，似乎歌单详情页的没有发生改变」—— 此前我只验证了侧栏封面，漏了详情页。

### 根因（两层，缺一不可修）
1. **接口层**：`fetchPlaylistDetail` 的 `timestamp` 只在 body 里。上游 apicache 缓存键是
   `hostname + originalUrl`，URL 恒定 → 改完封面立刻回读详情命中 2 分钟旧缓存。
   探针实测：无 query ts 读到 `pic=(空)`，带 query ts 或 `x-apicache-bypass: 1` 读到新 `custom/...`。
2. **组件层**：`Playlist.vue` 只在 `onMounted` 与 `gid` 变化时拉数据；编辑弹框是从**侧栏**右键打开的，
   不经过详情页任何生命周期，所以即便接口返回新数据也不会再请求一次。

### 修复
- `src/api/playlist.ts`：`fetchPlaylistDetail` 改 `{ params: { ids: gid, timestamp: Date.now() } }`。
- `src/stores/library.ts`：新增 `const revision = ref(0)`，`updatePlaylistInfo()` 成功后 `revision += 1`，
  并加入 return。
- `src/views/Playlist.vue`：新增 `refreshDetail()`（只重拉详情，**不动曲目列表**），
  `watch(() => library.revision, () => void refreshDetail())`。
  不用整页 `load()`：它会 `detail.value = null` + `tracks.value = []`，视觉上像刷新了页面。

### 实测
- 隔离实例（`--user-data-dir` + `--remote-debugging-port=9455`）+ 临时歌单端到端：
  右键侧栏 → 编辑歌单信息 → canvas 生成 600×600 图走真实 change 事件 → 保存
  → 详情页 `.head__cover img` 从占位变成 `http://c1.kgimg.com/custom/480/20261026/...jpg`，与服务端一致。
- `npx vue-tsc --noEmit` TC=0；`npx vite build` BUILD=0。
- 临时歌单已删净，回读确认仍是原来的 7 个歌单。

### 环境备忘
- 右键菜单类名是 `.ctx-menu__item`，不是 `context-menu`（我第一次写错，白跑一轮）。
- Electron 30 内置 Node 20.16 **没有全局 `WebSocket`**（`typeof WebSocket === 'undefined'`），
  CDP 客户端必须放在外部 Node 22 进程里，别塞进 Electron 主进程脚本。
- `Set-Content` 会把脚本写成 GBK，中文字面量在 Node 里报 `SyntaxError: Invalid or unexpected token`；
  探针脚本要么全 ASCII，要么用 `write` 工具落盘。
