## 把 KuGouMusicApi 打进安装包

### 结论
接收方**不需要**装 Node / 后端：主进程用 `process.execPath` + `ELECTRON_RUN_AS_NODE=1` 拉起上游。
但原来的 `electron-builder.json5` 没有 `extraResources`，`resources/KuGouMusicApi` 不存在，
分享出去的包会在「本地服务」里显示「未找到 KuGouMusicApi 工程目录」。

### 关键坑：后端目录不能直接复制
`KuGouMusicApi/node_modules` 是 pnpm 布局，`node_modules/express` 等全是指向
`/d/project/kugo/...` 的**绝对符号链接**，复制到别人机器必然 MODULE_NOT_FOUND。
→ 必须复制源码 + 用 npm 在生产模式重装扁平 node_modules。

### 改动
- `scripts/prepare-upstream.mjs`（新增）：复制 app.js/server.js/main.js/index.js/package.json/.env
  + module/util/public 到 `build/upstream`，写一份只含 dependencies 的 package.json，
  再 `npm install --omit=dev`。产物 22.7MB（原目录 117MB，devDeps 与 pnpm 重复存储被去掉）。
- `electron-builder.json5`：`extraResources: [{ from: "build/upstream", to: "KuGouMusicApi" }]`，
  正好对应 `upstream.ts` 里 `resolveApiDir()` 的 `process.resourcesPath/KuGouMusicApi`。
- `package.json`：`build` 前置跑 prepare 脚本，另加 `build:upstream` 单独入口。
- `.gitignore`：忽略 `build/upstream` 与 `release`。
- `electron/services/upstream.ts`：`app.isPackaged` 时把 `KUGOU_API_DEVICE_FILE` 指到
  `userData/upstream/device.json`。原因：上游把设备身份写在自身目录（`util/device.js` 的
  `__dirname/..`），安装目录在 AppImage / 签名后的 .app 是只读的，写失败就每次启动换设备号 → 触发风控 20028；
  更新安装包也会清掉它。开发期不设该变量，保持沿用仓库里的 `.device.json`。
- `KuGouMusicApi/util/device.js`（另一个仓库）：`IDENTITY_FILE` 支持 `KUGOU_API_DEVICE_FILE`，
  默认行为不变。

### 验证
- `node build/upstream/app.js --port=3999` 单独跑：`/search/song` 返回 480 条，
  `KUGOU_API_DEVICE_FILE` 指定的文件被写入。
- `electron-builder --dir` 产物：`resources/KuGouMusicApi` 内 node_modules 是扁平目录（非符号链接）。
- 实机启动 win-unpacked 的 exe：5 个进程、3000 端口返回真实数据、
  `%APPDATA%/music-app/upstream/device.json` 生成、安装目录没有被写入。

### 环境坑（会反复踩）
- 本机 `ELECTRON_RUN_AS_NODE=1`，直接跑打包后的 exe 会被当成 Node（报 `bad option`、无窗口、无子进程）。
  必须 `env -u ELECTRON_RUN_AS_NODE ./YourAppName.exe`。
- `electron-builder` 解压 winCodeSign 缓存时要建 darwin 的符号链接，非管理员会报
  `Cannot create symbolic link`。绕法：开启 Windows 开发者模式，或 `-c.win.signAndEditExecutable=false`
  （代价：exe 不带图标/版本信息）。
- 打包前 `appId` / `productName` 还是占位符 `YourAppID` / `YourAppName`，分享前要改。

### 完整 NSIS 打包（补记）
- `npm run build` 会依次跑 vue-tsc → vite build → prepare-upstream → electron-builder(NSIS)，
  产物 `release/<version>/<productName>-Windows-<version>-Setup.exe`，实测 85MB（含 27MB 上游）。
- **GitHub 下载 NSIS 工具链会 Bad Gateway**（本机网络），用镜像解决：
  `ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/ npx electron-builder ...`
- 同时仍需绕过 winCodeSign 的符号链接权限问题：加 `-c.win.signAndEditExecutable=false`
  （代价：exe 不带自定义图标/版本信息）。要保留图标就开 Windows 开发者模式。
- 验证包内上游：`resources/KuGouMusicApi/node_modules/express` 是实体目录（不是符号链接）。

## 外文歌词翻译（KRC 自带，无需外部翻译服务）

### 关键发现
酷狗 KRC 里带 `[language:BASE64]` 字段，base64 解出来是 JSON：
`{ content: [{ language: 0, lyricContent: [["译"], ["文"], ...] }] }`，
**与 KRC 的歌词行按行号一一对应**（含空行，91/91、65/65、93/93 都对齐）。
部分日文歌还会给第二块（罗马音），这里只取第一块。
LRC 格式没有这个字段 —— 所以只有走 KRC 的歌才有译文。

### 实现
- `utils/lyric.ts`：`LyricLine.translation?`；新增 `LANGUAGE_TAG` 正则 + `decodeTranslations()`
  （atob → Uint8Array → TextDecoder → JSON → 第一块 lyricContent，按行 join）。
  `parseKrc()` 先单独扫一遍取 `[language:]`，主循环用 `rawIndex` 计数（**空行也要占位**），
  按行号挂 `translation`；译文与原文相同则不挂。
- `stores/settings.ts`：新增 `lyricTranslation`（默认 true，持久化）。
- `views/Lyrics.vue`：每行下方渲染 `.lyric-line__trans`（14px / 当前行 17px）；
  右上角加翻译开关，仅当 `hasTranslation` 时显示，状态写回设置。
- `components/common/AppIcon.vue`：新增 `translate` 图标。

### 验证
- 搜「Shape of You」→ 播放 → 进歌词页：91 行、88 条译文（头部 3 行无译文，符合预期）；
  开关点击后 `.lyric-line__trans` 从 88 → 0 → 88；当前行译文 17px / rgb(166,174,192)。
- 中文歌不带 `[language:]`，不会出现重复译文行。

### 如果以后要给「没有译文的歌」做翻译
只能外接：本地小模型（体积/性能代价大）或云翻译/LLM API（需 key、有费用、要缓存）。
当前实现零成本、零延迟、不联网，优先走这条。

## KRC 结构调研：原文 / 译文 / 罗马音

以真实 KRC 验证（Lemon、打上花火、夜曲）：

- **正文**：`[行开始ms,行时长ms]<字偏移,字时长,?>字…`，逐字时间只在这里。
- **头部标签**：id / ar / ti / by / hash / al / sign / qq / total / offset / language。
- **`[language:...]`**：base64(JSON)，结构 `{version, content:[{language, type, lyricContent:string[][]}]}`；
  - `type: 1` = 中文译文；`type: 0` = 日文罗马音；`language` 都是 0，不能用它区分；
  - 每块行数与正文严格对齐（含空行占位）；
  - 块数 0/1/2 不固定，**顺序也不固定**：
    - Lemon：`[type1 译文, type0 罗马音]`
    - 打上花火：`[type0 罗马音, type1 译文]`
    - 夜曲：无 `[language:]`
  - 译文/罗马音都是整行字符串，没有逐字时间。

### 修复
`decodeTranslations` 原来固定取 `content[0]`，在「打上花火」这类歌曲上会把罗马音当译文显示。
改为优先 `type === 1` 的块，找不到再退回第一块。
实测：Lemon 54 行译文、打上花火 44 行译文、夜曲 0 行，均正确。
