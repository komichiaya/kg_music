# 2026-11-01

## 调研：上游是否有「关注歌手」类接口（结论：有，4 个）

用户提问「接口里有关注歌手吗」，通读 `../KuGouMusicApi/module` 后确认存在，本项目**尚未接入**
（`src/` 全量 grep `follow` 无命中，`Artist.vue` 无关注按钮）。

| 路由（POST） | 上游实现文件 | 真实上游地址 | 关键参数 |
|---|---|---|---|
| `/artist/follow` | artist_follow.js | `/followservice/v3/follow_singer` | id（歌手 id，上游会 Number() 转换） |
| `/artist/unfollow` | artist_unfollow.js | `/followservice/v3/unfollow_singer` | id（原样传字符串） |
| `/artist/follow/newsongs` | artist_follow_newsongs.js | `/feed/v1/follow/newsong_album_list` | last_album_id / pagesize(30) / opt_sort(1 时间 / 2 亲密度) |
| `/user/follow` | user_follow.js | `/v4/follow_list` | 无参数，merge=2 返回**歌手+用户混合**列表 |

其它相关：`/singer/list`（歌手分类列表，非关注）、`/user/follow/add|del`（关注**用户**，与歌手粉丝
体系是两套独立存储，勿混用）。

### 接入要点
- 鉴权：项目 `request.ts` 已统一注入 `Authorization: token=..;userid=..`，上游 server.js 会把该头
  解析合并进 `params.cookie`，而 `artist_follow.js` 读的正是 `params.cookie.token/userid` → **可直接用**，无需额外传参。
- 缓存：apicache 只缓存 GET，这 4 个都是 POST → 不需要 timestamp。
  > **更正（当天实测推翻）**：apicache 的缓存键是 `hostname + originalUrl`，**不看 method**，
  > POST 一样被缓存 2 分钟。所以关注/取关后立刻重拉 `/user/follow` 必须带 query `timestamp`，
  > 否则读到的是关注前的旧列表（实测：不带 ts 读 3 条，带 ts 读 4 条）。
- 关注态判定：`/artist/detail`（`/kmr/v3/author`）类型里目前没定义 `is_follow`，
  **未实测**（上游服务当时未运行，curl 127.0.0.1:3000 返回 000）。
  若 detail 无该字段，只能拉 `/user/follow` 列表比对 `singerid` 并靠 `jumptype` 过滤出歌手项。
  > **实测确认**：`/artist/detail` 响应里**没有任何关注字段**（拿到 `user_status:0` 这类无关字段），
  > 关注态只能靠 `/user/follow` 全表比对。`jumptype` 不可靠（歌手项也有 `jumptype:1`），
  > 判据应是「`singerid` 有值且 `userid === 0`」。
- 未验证：三个写接口的响应体结构与错误码（如重复关注是否报错）均未实测，接入前需先跑通一次。
  > **实测结果**：`/artist/follow` 重复关注 → `{"data":{"msg":"关注成功"},"status":1}`（不报错）；
  > 首次关注 → `{"data":{"rank":81677,"followtime":1793517324},"status":1}`；
  > `/artist/unfollow` 无论是否关注 → `{"data":{"msg":"操作成功"},"status":1}`。
  > 两个写接口都**幂等**，不需要先查后写。

## 实现：关注歌手 + 「我的收藏」页

用户需求（原话）：「在 @src/views/Artist.vue 详情头部加关注/已关注按钮，在 @src/views/Profile.vue 中添加
「我的收藏」入口，点击后跳转到关注的页面，里面有关注的歌手，收藏的别人创建的歌单」。

### 新增 / 改动文件
- 新增 `src/stores/follow.ts`：`artists / loading / error / pending / loaded`、`isFollowing(id)`、
  `load(userid, force)`（账号级去重 + inflight 合并）、`toggle(id, seed)`（幂等写 + 原地增删列表项）、`reset()`。
- 新增 `src/views/Favorites.vue`（`/favorites`，`requiresAuth`）：上「关注的歌手」圆形头像栅格、
  下「收藏的歌单」方形封面栅格，各自独立骨架屏与空状态；顶部「刷新」走 `Promise.all` 强制重拉。
- `src/api/artist.ts`：新增 `followArtist(id)` / `unfollowArtist(id)` / `fetchFollowedArtists()`，
  文件头补上「POST 也会被 apicache 缓存」的说明。
- `src/types/kugou.ts`：新增 `FollowedArtist { id, name, avatar, addTime }`。
- `src/stores/auth.ts`：`logout()` 里加 `useFollowStore().reset()`。
- `src/views/Artist.vue`：头部 `.head__meta` 下加 `.head__actions` + `.follow-button`
  （未关注=品牌渐变实心、已关注=描边次级且 hover 转红提示可取消）；`toggleFollow()` 未登录直接跳登录页并带 redirect；
  `onMounted` / `watch(auth.sessionChecked)` 触发 `follow.load()`。
- `src/views/Profile.vue`：stats 下方加 `.entry` 卡片（心形图标 + 标题 + 「N 位歌手 · M 个歌单」+ 右箭头），
  点击 `router.push({ name: 'favorites' })`。
- `src/router/index.ts`：注册 `/favorites`。
- 文档：`docs/开发文档.md` §4.4.3 表格加两行、新增 §4.4.8「关注歌手与「我的收藏」」、§6.4.1「useFollow」。
