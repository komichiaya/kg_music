### 踩坑与修复（重要）

1. **preload 必须产出 CJS**：`package.json` 有 `type: module`，vite-plugin-electron 默认把 preload 打成 `.mjs` 但内容是 CJS（含 `require`），Electron 报
   `require is not defined in ES module scope`，导致 `window.kugou` 全缺失。已改为
   `rollupOptions.output = { format: 'cjs', entryFileNames: 'preload.cjs' }`，主进程引用 `preload.cjs`。
2. **ELECTRON_RUN_AS_NODE 环境泄漏**：WorkBuddy 的终端环境自带 `ELECTRON_RUN_AS_NODE=1`，
   `pnpm dev` 拉起的主进程会被当普通 Node 执行，报
   `The requested module 'electron' does not provide an export named 'BrowserWindow'`。
   已在 `vite.config.ts` 顶部 `delete process.env.ELECTRON_RUN_AS_NODE`。
   上游子进程的 spawn 里仍显式设该变量（用 Electron 二进制跑 Node，打包后无需装 Node）。
3. **打包必须 `base: './'`**：否则 `dist/index.html` 引用 `/assets/*`，`file://` 解析到磁盘根目录导致白屏。
4. axios 经 pnpm 安装后 `node_modules/axios` 是空壳（已知 pnpm 中断问题），用 Junction 指向
   `node_modules/.pnpm/axios@1.20.0_<peer后缀>/node_modules/axios` 修复。
5. 首次进入懒加载页（Settings）时 Vite 现场优化 element-plus 依赖会触发一次 reload，属正常现象。

### 关键发现（务必记住）

- **取流 hash 必须与 quality 匹配**：128→`FileHash`、320→`HQFileHash`、flac→`SQFileHash`、
  high→`ResFileHash`。用 128 的 hash 请求 320 会直接 `status=2`（看起来像没版权，其实是 hash 不匹配）。
- `album_audio_id` 用搜索结果的 `MixSongID`（不是 `Audioid`）。
- 付费曲完整版失败时 `fail_process=["pkg","buy"]`；带 `free_part=1` 可拿 60s 片段，
  `hash_offset.end_ms` 标出裁剪点，音频真实时长约等于试听长度。
- 搜索封面字段 `Image` 含 `{size}` 占位符，替换成 480。
- 单实例锁会让「第二个 Electron 实例」立即退出：自动化验证前必须先清干净残留进程。

### 验证

- 自动化 E2E（临时 executeJavaScript 钩子，验证后已移除）：
  `/search?q=纯音乐` 渲染 30 行 → 点首条 → 播放器标题/歌手正确，进度 0:03→0:04 / 3:43，无错误条；

### 关键事实

- 歌词接口成功标志是 **status=200**；`/search/lyric` 候选在**根节点** `candidates`（不在 `data`）。
- KRC：`[行开始ms,行时长ms]<字偏移ms,字时长ms,0>字...`，字偏移相对行开始（绝对时间 = 行开始 + 偏移）。
- LRC 支持一行多时间标签与 `[offset:±ms]`，`.74` 要按百分秒转 740ms。
- 透明窗口必须给 html/body/#app 设 transparent，否则圆角外露黑边。
